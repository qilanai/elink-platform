# Elink Platform conventions

- This repository owns the creation modules, shared services, contracts and local orchestration. Production user routes are `/apps/workspace/` (independent creative app), `/apps` (compatibility application center), and `/apps/studio/` (full-page Studio) under `https://api.elinkhk.com`. new-api owns these routes.
- `apps/studio` is ordinary source owned by this repository, imported once from Open AI Canvas. Read its AGENTS.md before changing it; preserve original licensing and attribution. `source-origins.json` records historical provenance, not an upgrade pin. Do not restore a submodule, upstream merge workflow or automatic upstream updater.
- The independent creative workspace at `/apps/workspace/` is the primary user app; `/apps` remains a compatibility application center. Launch Studio in a new browser tab as the full Canvas application under /apps/studio/; do not embed its editor in the dashboard shell. Generated website previews still require sandbox isolation.
- Keep Canvas's own React root, editor layout, routes and toolchain. new-api owns the application entry, account, model catalog and billing; Studio owns its document and resource APIs. Communicate over HTTP, not absolute sibling imports.
- new-api remains a separate repository and is accessed over HTTP. Do not import its private packages, share application tables or copy its frontend into this repository.
- All local data, credentials and diagnostic artifacts belong in ignored `.local/`. Never commit tokens, cookies, database URLs containing passwords, or generated media.
- Local orchestration must bind published ports to loopback and use a separate Compose project. Production manifests remain in the existing deployment repository.
- The standalone workspace uses new-api's existing dashboard session through `/api/ext/apps/*`. Studio services enforce resource ownership using verified server identity; browser-supplied user IDs are not credentials. The legacy login is a local migration reference, not a compatibility requirement for the new product.
- new-api is the only source of model configuration, channels, credentials, group permissions and pricing. All Studio model selectors, including assistant/audio/image/video paths, select existing permitted new-api models. Capability adapters may describe protocols and constraints, but must not create a second provider/credential/price catalog.
- Remove Studio credits, payments, check-in bonuses, redemption codes and local charge/refund dependencies from the production UI, APIs and task path. Merely hiding controls or disabling a feature flag does not complete removal. Preserve historical data for explicit migration/archival; do not silently convert old credits into new-api quota.
- Refactor Studio business logic as needed. Do not preserve old channel, credit, login or task contracts at the expense of the hosted product. The current API and Worker share `apps/studio/backend`.
- Do not implement identity or billing with default users, shared administrator keys, fabricated balances, or authentication bypasses. Use bounded server-side task execution authorization and the existing new-api relay/billing checks. Hosted mode validates the main session for every request. Task credentials are short-lived, encrypted at rest, scoped to their owning user and rechecked by new-api during execution.
- Business UI must reflect actual availability. Unimplemented applications must not have working-looking launch buttons or fabricated activity.
- Use Bun for the platform frontend. Studio retains its own toolchain and is excluded from root workspaces.
- Keep Go services independently buildable with `GOWORK=off`. Run focused behavioral tests, vet and builds for changes; verify Compose configuration and real startup for orchestration changes.
- new-api alone retains its own upstream fork workflow. Platform releases and optional imports from Canvas are reviewed and maintained here; a new upstream release does not trigger a merge or deployment.

- `apps/workspace` owns the independent home/navigation and the LobeHub v0.162.25 (MIT) chat subset. Serve at `/apps/workspace/`; old `/apps/chat` and `/apps/lobehub/` redirect to its chat route. Preserve LICENSE/NOTICE and source mappings. Do not add upstream sync or independent provider credentials. Only host-authorized chat-completions models are selectable.
